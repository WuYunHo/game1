# 02 · 空间与镜头

> 解决「人物像在前进，门和怪又在朝人移」的违和；并让移动符合像素/格子审美。

## 1. 设计原则

1. **门与多数关卡物件相对地图静止。**
2. **玩家在地图上前进 + 左右换道。**
3. **只有进入追击态的飞飞鼠才主动改坐标靠近玩家。**
4. **左右移动离散、对齐车道网格**（俄罗斯方块式格子感，而非无级滑轨）。

## 2. 逻辑坐标系

推荐使用格子坐标，再投影到屏幕：

```
lane  ∈ 0 .. LANE_COUNT-1     // 默认 5 车道
row   ∈ 0 .. MAP_ROWS-1       // 沿前进方向增加
```

- 世界前进方向：`+row`（或连续 `y`，但门/刷怪点仍吸附到整数行）。
- 玩家状态：`player.lane`（整数）、`player.row` 或 `player.y`（匀速增加）。
- 门：生成时写入 `(laneSpan, row)`，**之后不再改 row**。
- 站岗敌：出生在 `(lane, row)`，未 aggro 前不动或只在原格动画。
- 追击敌：aggro 后每帧向玩家 lane/row 靠近。

### 2.1 车道建议

```
lane:  0     1     2     3     4
      左2   左1   中    右1   右2
```

- 一排双门：**同类型等宽**，各占 5 格棋盘（左 cols 1–5，右 cols 6–10）；车道归属 `lane <= 1` 左，否则右。
- 玩家换道：一次输入 ±1 lane，带短缓动（2～4 帧视觉插值），逻辑车道立即切换或缓动结束再切换（推荐：**输入即改逻辑 lane**，表现插值跟随）。

## 3. 镜头方案

### 方案 A（推荐）：相机跟随玩家前进

- 逻辑：世界静止，`camera.y ≈ player.y - offset`。
- 观感：玩家大致留在屏幕偏下，前方露出未到达的门与敌。
- 优点：最符合「地图静止」的叙事；调试直观。

### 方案 B：玩家钉屏，地面卷轴

- 逻辑仍用绝对 `y`；渲染时所有物体 `screenY = worldY - cameraY`。
- 观感更像传统跑酷，但文档与调试必须强调「逻辑静止」。

**首期选定：方案 A。** 若微信性能或表现需要，可在不改逻辑的前提下换成 B。

## 4. 「俄罗斯方块式」门与移动——含义

此处指**格子感**，不是门像方块一样下落贯穿全关：

| 做法 | 说明 |
|---|---|
| 换道按格 | 左右一格一格切 |
| 门占格 | 门宽对齐车道，边缘贴网格线 |
| 关卡按行铺 | 每隔 N 行布置门行 / 敌行 |
| 入场动画（可选） | 门生成时可「落入」目标格后锁定；锁定后静止 |

禁止：门在逻辑上持续 `depth += dt` 飘向玩家（旧版模型）。

## 5. 相对运动对照

| 对象 | 相对地图 | 屏幕上可能怎样动 | 原因 |
|---|---|---|---|
| 地面砖、门 | 静止 | 因相机跟随而向下滚出 | 相机动 |
| 站岗飞飞鼠 | 静止 | 同上 | 相机动 |
| 追击飞飞鼠 | 移动 | 相对玩家靠近 | AI |
| 玩家小队 | 移动 | 左右换道 + 略置于屏幕下方 | 输入 + 镜头 |
| 子弹 | 移动 | 向前飞或瞬时命中 | 战斗 |

## 6. 发现与追击的空间规则（摘要）

详见 `05-敌人与追击AI.md`。

- 发现距离：以格子或世界距离计，例如曼哈顿距离 / 前方锥形。
- 未发现：不动（或原地 idle）。
- 已发现：向玩家 lane 对齐并减小 row 差。

## 7. 旧版迁移注意

旧 `Encounter.depth`（0→1 接触）应废弃为地图 `row`/`y`。  
Presentation 若暂留假 3D 透视，只能作为**投影函数**，不能再当「谁在动」的真相来源。
